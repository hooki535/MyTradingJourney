# Supplied covers and the reading room

The user's `pdf.zip` contains JPEG images only. It provides 23 distinct matching book covers, plus duplicates. Each selected JPEG is copied byte for byte into `assets/book-covers`; the manifest in `assets/book-artwork.js` records its dimensions and SHA-256. There is no Psychology of Money cover in this ZIP, so that book retains its existing SVG cover. No book PDFs were added from this archive.

The homepage shelf, Library grid, Book Hubs, decorative workspace stacks, and reader thumbnails use the selected covers. Catalog artwork takes priority over older auto-generated account cover thumbnails; existing account cover records are retained. Custom personal-book covers still use account storage. `css/book-shelf.css` makes the card follow the cover's intrinsic proportions, removes the padded image stages, and keeps artwork uncropped on desktop and mobile.

The Book Hub's Add PDF picker has been removed. Library upload controls are hidden, including the legacy PDF picker and batch upload actions. Their compatibility inputs and old account import/save handlers remain to avoid breaking existing records and imports. There are no visible Add/Upload PDF prompts in the Library or Hub. Books with an existing local PDF, account PDF, bundled PDF, or official source link remain readable. Others show **PDF unavailable** while retaining all original Hub guides and tools. Unavailable reader links show a useful empty state leading back to the Hub; they do not invite another upload or promise a release date.

`css/reader-studio.css` provides a dedicated full-viewport reading room: document cover/title header, grouped navigation and paper controls, a large centered canvas, notebook on the right, quiet status and progress bars, and responsive notebook drawer. White, sepia, dark paper, and Focus mode remain supported. The existing PDF.js rendering geometry, text selection, highlights, ink, bookmarks, search, and notebook exports remain in place. A keyboard fix stops notebook tab arrows/Home/End from bubbling into PDF page navigation. The notebook now has an explicit close control.

Validation: all 184 existing Node tests pass. Browser QA verifies original cover proportions, missing-PDF labels, absence of Add PDF actions, loading of a bundled 72-page PDF, page navigation, notebook keyboard behavior, persisted device annotations/bookmarks, paper/zoom controls, drawing mode, and mobile drawer layout without document overflow. HTTP-preview-only fixtures supply a known sample fingerprint/UUID helpers and seed an isolated `qa-richest-reader` device file; they are ignored and are not published. Production keeps real WebCrypto and the existing account/local annotation stores.
